모바일 사진 하자점검–PostgreSQL 연동 현황 및 구현 로드맵

v1.0 · 2026-07-27 · 로컬 PostgreSQL 기준

결론

현재 앱은 사진·하자·의견을 폰에 저장하고, 통신이 정상일 때 재전송하는 골격과 FastAPI→PostgreSQL 하자 저장 API까지 구현되어 있습니다. 다만 지금 상태만으로는 실제 현장 사진 파일·스티커 사진·완전한 최종 분류를 PostgreSQL에 안전하게 보관하는 연결이 완성되지 않았습니다. 다음 구현의 우선순위는 사진 업로드 저장소 연결, 앱↔DB 분류 필드 정합, 실기기 E2E 저장 검증입니다.

현재 데이터 흐름

카메라 촬영 → 앱 전용 파일 저장소 → Room DB(defects, defect_photos, sync_queue) → 정상 네트워크 감지 → FastAPI /v2/field/sync/batches → PostgreSQL apartment_ai.defects

구현 완료·동작 기반

영역상태확인 내용
현장 사진 촬영구현CameraX 촬영본을 앱 내부 파일 경로와 Room의 defect_photos에 저장
하자·의견 로컬 저장구현하자 위치, 분류, 원문 의견, 표준화 의견, 사진 메타데이터를 Room에 저장
오프라인 큐구현sync_queue와 재시도 정책, 네트워크 정상화 감지, 앱 재시작 시 미완료 큐 복구
서버 하자 API구현세대 조회, 점검 세션, 앵커, 하자 upsert, summary, 마감, batch sync 경로 존재
PostgreSQL 저장소구현PostgresInspectionStore가 session/defect/media 테이블과 멱등키·revision 충돌을 처리
로컬 DB 검증검증 이력 있음HTTP_FIELD_FLOW=PASS, PERSISTENCE=postgresql, 전체 Python 테스트 148 passed 이력
실기기 서버 주소 주입구현PINSET_AI_API_BASE_URL Gradle 속성으로 가능. 기본값은 빈 값이므로 주소를 넣지 않은 APK는 동기화하지 않음

아직 구현되지 않았거나 정합이 필요한 항목

우선항목현재 문제구현 방향
1사진 실저장미완료앱의 사진 업로드 API는 현재 개발용 메모리 서비스에 저장되며 PostgreSQL media 레코드·파일 저장소와 연결되지 않음. S3/MinIO 또는 로컬 파일 저장소와 media 등록 API를 결합
2분류 필드 정합미완료Android payload의 work_kind/surface/final_path와 DB가 받는 final_work_kind_code/final_location_code/final_part_code/final_cause_code가 일치하지 않아 일부 최종 분류가 NULL로 저장될 수 있음
3스티커·메모 사진미완료앱에는 저장·표시되지만 서버 동기화는 기본/광역 사진 중심이며 메모 사진 role·object key·DB media 등록이 빠져 있음
4사진 없는 하자제한앱 UI에서는 가능하나 동기화 업로더가 사진 없음을 재시도 오류로 처리. 가상 하자 상태를 서버 계약에 추가
5점검 세션 마감 전송미연결서버에는 complete API가 있으나 앱의 “세대 점검 마감”과 서버 complete 호출의 연결을 확인·구현해야 함
6실사용 인증미완료현재 로그인은 앱 내 데모/권한 게이트 수준. 서버 인증·토큰·점검자 ID 전달·권한 검증 필요
7백그라운드 보장보강 필요현재 앱 실행 중 재시도 중심. 장시간 종료 상태에서도 보장하려면 WorkManager 기반 영속 작업 추가
8운영 보안미완료debug HTTP는 실험용. 운영은 HTTPS, 토큰, 서버 측 감사 로그, 암호화 저장소 필요

권장 구현 순서

  1. 1단계: 실기기 기본 E2E — USB ADB reverse 또는 동일 Wi-Fi에서 앱 1건 사진·의견을 서버로 보내고 PostgreSQL defects에 저장됐는지 조회로 확인
  2. 2단계: DB payload 정합 — Android의 위치·부위·상세·공종·원인·우선순위 필드를 API 계약 이름으로 통일하고 자동 테스트 추가
  3. 3단계: 사진 저장 — 이미지 원본을 객체 저장소에 업로드하고 object_key·sha256·role을 apartment_ai.media에 등록. 기본/광역/스티커·메모를 모두 지원
  4. 4단계: 세션 마감·집계 — 앱의 세대 점검 마감 버튼이 서버 complete 및 summary와 연결되도록 구현
  5. 5단계: 인증·운영 전환 — 점검자 로그인과 토큰 인증, HTTPS, 운영 DB·객체 저장소 환경을 분리

다음에 바로 구현할 항목

권장: 1단계 실기기 기본 E2E 연결입니다. 서버 실행→폰 API 주소 주입→사진 1건 전송→PostgreSQL 확인을 먼저 끝내면, 사진 파일 저장과 분류 정합을 실제 데이터로 이어갈 수 있습니다.

보안·운영 주의

이 문서는 로컬 개발 PostgreSQL 기준입니다. 운영 AWS RDS에는 현재 직접 쓰기 검증을 수행하지 않으며, DB 비밀번호·DSN·접속 문자열은 앱·문서·로그에 넣지 않습니다.
