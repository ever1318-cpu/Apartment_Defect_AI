1. 이번 반영 범위

앱의 입력·사진·의견·마감 화면을 현장 사용 흐름으로 정돈하고, 저장된 이미지와 메타데이터를 휴대폰에서 다시 조회하는 하자DB 화면을 추가했다. 사진 또는 의견이 누락되어도 점검 건을 저장·집계할 수 있도록 안전한 기본값을 적용했다.

2. 현장 화면 흐름

[초기환경 / 세대 선택] ├─ 앵커 촬영 (세대 최초 1회만) ──┐ ├─ 하자 입력 ────────────────────┼→ [하자사진] → [하자의견] → 저장 ├─ 보고서 │ │ └─ 하자DB ─ 저장 사진·메타데이터 조회 ┘ ↓ [전송 및 마감] 휴대폰 로컬 보관 → VPN/네트워크 → Field API → PostgreSQL + field-media

초기환경

동·호수와 평형을 기준으로 평면도·세대 정보를 불러오며, 앵커 촬영과 하자 입력, 보고서, 하자DB로 바로 이동한다.

하자사진

기본은 근경 1장이며 필요 시 근경 + 원경을 선택한다. 촬영 후 별도 판별확인 화면 없이 하자의견 입력으로 이동한다.

하자의견

음성인식 또는 문자 입력을 사용한다. AI 추천은 사진·문자 근거를 색상으로 구분하고, 최종 의견은 점검자 의견과 AI 결과를 함께 편집한다.

완료·조회

보고서에서 건수와 통계를 확인한 뒤 전송 및 마감한다. 하자DB에서는 세대별 저장 사진과 메타데이터를 갤러리로 확인한다.

3. 최신 UI/UX 적용 내역

화면·기능반영 내용상태
초기환경하단 메뉴에 보고서, 하자DB를 함께 배치했다. 앵커 설정·촬영은 최초 1회만 노출하며 이후에는 앵커 위치 텍스트와 평면도 표시로 대체한다.구현
라이브 디텍션기본 촬영 모드를 근경 1장으로 변경하고, 근경 + 원경 선택을 유지했다. 촬영 완료 시 하자의견 화면으로 바로 전환한다.구현
하자의견 상세표현을 AI분석 추천 :사진/문자로 단순화했다. 번호 1·2를 크게 표시하고, 최종 입력 영역은 점검자 의견, AI 종합으로 정리했다.구현
AI 추천즉시 규칙 기반 추천을 먼저 표시하고, Gemini 설정이 완료된 경우 사진·점검자 의견·센서 문맥을 사용한 LLM 결과로 갱신한다. 네트워크 또는 키 미설정 시 안전한 규칙 기반 결과를 유지한다.구현
사진·의견 누락사진이 없으면 가상 참고 이미지 · 실제 촬영 없음이 명시된 도식 이미지를 생성한다. 의견이 없으면 위치·상세부위·유형·공종을 조합한 기본 추천을 저장한다.구현
보고서심각도·공종·방 통계를 한 단으로 축약하고 가운데 정렬했다. 공종의 기타는 인접 값과 혼동되지 않도록 간격을 보정했다.구현
마감최근 하자 목록 화면에서 전송 및 마감을 실행한다. 동기화 미완료가 있으면 마감을 보류하고 사유를 안내한다.구현
상단 통신 표시서버 /health를 주기적으로 확인한다. VPN 주소(100.x)를 사용하는 경우 VPN 연결·확인중·미연결 상태로 표시한다.구현
하자DB 갤러리동·호 풀다운, 서버 저장 매체 갤러리, 이미지·메타데이터 조회, 데이터 없음·통신 오류 안내를 제공한다. 가상 참고 이미지는 별도 표시한다.앱 구현

4. 저장·동기화·조회 아키텍처

S25 현장 앱 ├─ Room/로컬 파일: 사진·메모·스티커 사진·메타데이터 임시 보관 ├─ WorkManager: 통신 복구 시 업로드 재시도 └─ HTTPS 또는 Tailscale VPN API │ ▼ FastAPI Field API (포트 8001) ├─ /v2/media/uploads/{id} 이미지 업로드 ├─ /v2/field/sync/batches 하자·세션 동기화 ├─ /v2/field/gallery/households 세대 선택 목록 └─ /v2/field/media/{id}/content 저장 이미지 조회 │ ▼ PostgreSQL (하자·세대·세션·메타데이터) + workspace/field-media (실제 이미지 파일)

이미지 파일명은 동·호·위치·상세부위·타임스탬프 등 메타데이터를 반영할 수 있으며, DB에는 원본 파일의 식별자·경로·분류값을 함께 저장한다. 업로드 전에는 휴대폰 로컬 큐에 유지하므로 현장 통신 품질이 낮아도 입력 데이터가 즉시 사라지지 않는다.

5. 운영 반영 확인 사항

앱 코드에는 하자DB 조회 API와 갤러리 화면이 반영되어 있다. 다만 실행 중인 API 프로세스가 이전 코드인 경우 /health는 정상(200)이어도 /v2/field/gallery/households가 404일 수 있다. 이는 VPN 불량이 아니라 서버 프로세스 재시작이 필요한 배포 상태다.

  1. 기존 Field API를 종료한다.
  2. D:\AI_projects\Apartment_Defect_AI\scripts\run_field_postgres_server.ps1 -Port 8001로 최신 서버를 시작한다.
  3. PC에서 Invoke-RestMethod http://127.0.0.1:8001/v2/field/gallery/households를 실행해 목록 응답을 확인한다.
  4. 휴대폰 앱의 API 주소를 PC Tailscale 주소인 http://100.116.105.9:8001로 설정하고 하자DB를 새로고침한다.

실제 운영 환경에서는 외부 공개 HTTP 대신 인증, HTTPS, 접근제어를 적용한 서버 주소로 전환해야 한다. 현재 Tailscale 주소는 현장 검증망 용도다.

6. 검증 결과 및 다음 현장 점검

코드 검증

  • 백엔드 갤러리 관련 테스트: 15건 성공
  • Android :app:testDebugUnitTest 성공
  • Android Debug APK 조립 성공

현장 수용 기준

  • 사진 1장 저장 후 앱 상태가 전송 완료가 되는지
  • 보고서의 전송 및 마감 후 세션이 완료되는지
  • 하자DB에서 동일 동·호의 사진·메타데이터가 조회되는지
  • VPN을 끊었다가 복구했을 때 자동 재전송되는지

주의 사항

  • 가상 참고 이미지는 실제 현장 증빙 사진이 아니다.
  • AI 추천은 점검자의 최종 검토·수정을 전제로 한다.
  • 마감은 미전송 매체가 모두 처리된 뒤에만 완료된다.

7. 결론

현재 UI/UX는 현장 입력 → 로컬 보관 → 통신 복구 시 전송 → 서버 저장 → 휴대폰 갤러리 재조회라는 운영 순환을 갖추었다. 다음 실기기 확인의 핵심은 최신 API 프로세스를 재시작한 뒤, VPN 상태에서 하자DB의 동·호 목록과 저장 이미지가 정상 조회되는지 검증하는 것이다.
