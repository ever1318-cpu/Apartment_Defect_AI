AI 하자점검 시스템 아키텍처 v8.0

기준일: 2026-07-27 · Android 현장 앱, 오프라인 동기화, FastAPI, 로컬 PostgreSQL 및 사진 저장소

핵심 원칙: 현장에서는 통신이 끊겨도 사진과 하자정보를 휴대폰에 먼저 저장합니다. 통신이 확인되면 서버로 재전송하며, 모든 전송이 끝난 뒤에만 해당 세대의 서버 세션을 마감합니다.

1. 전체 데이터 흐름

① 점검자 휴대폰

PinSet Android 앱

사진 촬영·STT·하자의견·위치핀·세대 마감

② 휴대폰 로컬 DB

Room / 파일 저장소

세션, 하자, 사진 경로, 전송 큐를 즉시 보관

③ 오프라인 동기화

OfflineSyncManager

네트워크 복구 시 대기·재시도 항목을 순차 전송

④ 현장 API

FastAPI :8001

세대 조회, 사진 업로드, 하자 동기화, 세션 집계·마감

⑤ 서버 저장

PostgreSQL + field-media

구조화 하자 데이터와 원본 사진 파일을 분리 보관

4. 세대 마감 안전장치

확인 순서앱 동작사용자에게 보이는 결과
1. 로컬 전송 큐 검사해당 세대의 PENDING·RETRY·CONFLICT 항목 수를 계산미전송 사진 또는 하자정보가 있으면 건수를 안내하고 마감 중지
2. 즉시 전송 시도통신 가능 시 대기 큐를 한 번 비우도록 동기화 실행전송 성공 시 다음 단계, 실패 시 통신 확인 안내
3. 서버 세션 검증안정적인 client UUID로 서버 세션을 조회하고 서버 집계를 확인서버에 하자가 없거나 응답 오류면 마감 중지
4. 서버 세션 완료revision을 사용해 세션을 COMPLETED로 변경전송 건수·세션 마감 완료 메시지 후 다음 동·호수 초기 화면으로 이동

5. 다음 구현 우선순위

  1. 실제 현장 점검 1세대를 끝까지 입력하고, PostgreSQL의 media·defects·inspection_sessions 값을 대조한다.
  2. 서버 사진 저장소를 로컬 폴더에서 S3 등 운영용 객체 저장소로 전환하고 접근 권한·보존 정책을 적용한다.
  3. 서버 인증 토큰과 점검자 권한을 적용한다. 현재는 개발용 로컬 API 연결 구조다.
  4. ConvNeXt 이미지 분석과 텍스트 분석 결과를 서버 작업으로 실행하고, 점검자 확정값을 학습용 피드백 데이터로 축적한다.
