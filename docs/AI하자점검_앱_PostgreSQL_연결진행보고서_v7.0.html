1. 연결 구조 확정

Android 앱은 Room DB에 먼저 저장하고 OfflineSyncManager가 네트워크 회복 시 FastAPI로 재전송합니다. FastAPI는 PostgresInspectionStore를 통해 PostgreSQL의 apartment_ai 스키마에 세대·점검 세션·하자·미디어를 저장합니다.

구간구현 위치역할
앱 로컬PinSetApplication / AppDatabase사진·의견·하자와 sync_queue 저장
재전송OfflineSyncManager / DefectSyncUploader대기·재시도·충돌 상태 관리
HTTP APIfield_postgres_entrypoint.pyhousehold resolve, session, anchor, sync batch
DBPostgresInspectionStore트랜잭션·멱등키·revision 충돌 처리

2. PC에서 서버 실행

cd D:\AI_projects\Apartment_Defect_AI
$env:LOCAL_APARTMENT_DB_HOST="127.0.0.1"
$env:LOCAL_APARTMENT_DB_PORT="5432"
$env:LOCAL_APARTMENT_DB_NAME="apartment_defect_local"
$env:LOCAL_APARTMENT_DB_USER="postgres"
$env:LOCAL_APARTMENT_DB_SSLMODE="disable"
$env:LOCAL_APARTMENT_DB_PASSWORD = Read-Host "Local PostgreSQL password"
.\scripts\run_field_postgres_server.ps1

정상 상태는 http://0.0.0.0:8000에서 Uvicorn이 실행되는 것입니다. 비밀번호는 로그·파일·앱에 저장하지 않습니다.

3. Android 연결 방식

권장: USB ADB

adb reverse tcp:8000 tcp:8000
cd D:\AI_projects\PinSet-App
.\gradlew.bat -p android :app:assembleDebug -PPINSET_AI_API_BASE_URL=http://127.0.0.1:8000 --no-daemon

debug 빌드에는 로컬 HTTP 허용 설정이 포함되어 있어 S25에서 USB로 PC의 8000 포트에 접근할 수 있습니다.

대안: 같은 Wi‑Fi

ipconfig
# 예: PC IPv4가 192.168.0.20인 경우
.\gradlew.bat -p android :app:assembleDebug -PPINSET_AI_API_BASE_URL=http://192.168.0.20:8000 --no-daemon

Windows 방화벽에서 TCP 8000 인바운드를 허용하고, 폰과 PC가 같은 사설망에 있어야 합니다.

4. 검증 결과

  • PostgreSQL 저장소 단위·HTTP E2E 테스트: 4 passed
  • 전체 Python 테스트: 148 passed, 6 skipped
  • 기존 로컬 DB 초기화 결과: buildings=20, households=2000
  • 이전에 확인된 HTTP 흐름: HTTP_FIELD_FLOW=PASS, PERSISTENCE=postgresql

현재 PowerShell 세션에는 DB 환경변수가 없어 이 세션에서 실DB 재검증은 비밀번호 입력 후 수행해야 합니다. 운영 AWS RDS에는 연결·쓰기 작업을 수행하지 않았습니다.

5. 실제 저장 확인 순서

  1. 로컬 PostgreSQL 서비스를 시작하고 환경변수·비밀번호를 설정합니다.
  2. run_field_postgres_server.ps1로 API를 실행합니다.
  3. verify_field_postgres_http.ps1를 실행해 세대 조회→세션→앵커→하자→마감 흐름을 확인합니다.
  4. ADB 연결 후 adb reverse tcp:8000 tcp:8000를 설정하고 API 주소를 주입해 APK를 설치합니다.
  5. 앱에서 하자 1건을 저장한 뒤 상세 화면의 동기화 상태가 ‘서버 저장 완료’인지 확인합니다.
  6. PostgreSQL에서 조회 전용으로 최근 세션·하자를 확인합니다. UPDATE/INSERT/DELETE는 검증 단계에서 직접 실행하지 않습니다.

6. 사진 없는 하자

사진 없이 입력한 하자는 앱 로컬에서는 가상 하자·사진 없음으로 표시됩니다. 서버 동기화 시 이미지가 없다는 사실을 유지한 메타데이터로 전송하며, 사진 필수 경로와 혼동하지 않도록 별도 상태값을 사용해야 합니다.
