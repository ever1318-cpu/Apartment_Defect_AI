공용부·기타 하자 입력 v5.2

동·호에 귀속되지 않는 지하주차장, 계단실, 복도, 외부 보도, 관리동 등의 하자 사진·의견·메타데이터를 독립적으로 저장·전송하는 기능

2026-07-28 · Android · FastAPI · PostgreSQL

1. 구현 결과

인트로 화면에 공용부·기타 버튼을 추가했다. 발생 위치를 입력하면 세대 선택을 거치지 않고 라이브 촬영 → 하자의견 입력 → AI 추천 → 저장 → 전송 및 마감 흐름으로 이동한다.

2. 현장 사용 흐름

인트로 └─ 공용부·기타 └─ 발생 위치 입력 (예: 106동 지하주차장 / 단지 보도 / 관리동) └─ 사진 입력 → 하자의견·스티커 사진 → AI 추천·최종 저장 └─ 로컬 보관 → 네트워크 복구 시 DB 전송 → 전송 및 마감

앱 내 세션은 공용부 · 발생 위치로 표시된다. 하자 분류의 위치 값도 입력한 공용부 위치를 우선 사용하므로 세대 평면도 방 이름으로 잘못 기록되지 않는다.

3. DB 저장 구조

점검 유형

inspection_kind = COMMON_AREA로 세대 하자와 명확히 구분한다.

위치 메타데이터

common_area_label에 점검자가 입력한 공용부·기타 장소를 저장한다.

기술용 연결

기존 하자·이미지 동기화 파이프라인을 안전하게 재사용하기 위해 서버 내부에는 COMMON / 0000 전용 레코드를 사용한다. 화면에는 공용부·기타로만 표시한다.

이 방식은 공용부 사진, 음성·문자 의견, 스티커·메모 사진, AI 분류 결과, 전송 상태를 기존 세대 하자와 동일한 수준으로 보관하면서도 세대 통계와 혼동하지 않게 한다.

4. 하자DB 표시

  • 공용부 기록도 전송 및 마감 완료 후에만 하자DB 조회 대상이 된다.
  • 하자DB 풀다운에서는 기술 코드 대신 공용부·기타 → 공용부 기록으로 표시된다.
  • 세부 갤러리에는 입력한 공용부 위치, 하자 의견·분류, 실제 또는 가상 참고 이미지가 표시된다.
  • 점검매니저의 세대 수 통계에는 공용부 기록을 포함하지 않는다.

5. 적용 절차

이번 기능은 PostgreSQL 스키마에 공용부 점검 유형과 전용 레코드를 추가하므로, APK 설치 전에 로컬 DB 마이그레이션을 한 번 실행해야 한다.

  1. 서버를 중지한다.
  2. D:\AI_projects\Apartment_Defect_AI에서 .\scripts\setup_local_field_db.ps1를 실행한다.
  3. 완료 후 .\scripts\run_field_postgres_server.ps1 -Port 8001로 서버를 재시작한다.
  4. 최신 APK를 설치한 뒤 공용부·기타 하자를 한 건 저장·전송·마감한다.

6. 검증 결과

  • 백엔드 API 테스트: 13건 성공
  • Android Debug APK: 빌드 성공
  • 실제 PostgreSQL 반영 및 휴대폰 설치는 위 적용 절차 후 수행한다.
