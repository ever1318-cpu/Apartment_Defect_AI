통신 음영 동에서도 촬영과 하자 입력이 중단되지 않는 Android 구조 · 2026-07-24

1. 구현 결론

하자 사진과 의견·분류·위치정보는 네트워크와 무관하게 휴대폰에 먼저 저장되며, 검증된 인터넷 연결이 회복되면 서버 API를 통해 자동 전송됩니다.

촬영 → 앱 전용 파일 저장 → Room 하자·사진·동기화 큐 단일 트랜잭션 → 즉시 현장업무 계속 → 통신 회복 감지 → 이미지 업로드 → /v2/sync/batches → 서버 확인 → 완료

2. 안전 원칙

로컬 저장 우선

전송 성공 여부와 상관없이 사진 원본과 하자 메타데이터가 먼저 휴대폰에 남습니다.

DB 직접 접속 금지

Android 앱은 AWS RDS에 직접 연결하지 않고 인증된 서버 API만 호출합니다.

중복 방지

작업 UUID를 미디어 업로드와 배치 동기화의 Idempotency-Key로 반복 사용합니다.

서버 확인 후 완료

applied 또는 duplicate 응답을 받은 경우에만 완료 상태로 전환합니다.

상태의미

5. 앱 동작

  • 앱 시작 시 이전 버전에서 저장됐지만 큐가 없는 하자를 자동 등록합니다.
  • 네트워크는 단순 연결이 아닌 Android의 NET_CAPABILITY_VALIDATED 상태를 확인합니다.
  • 앱이 실행 중이면 네트워크 회복 콜백으로 즉시 전송합니다.
  • 앱이 재시작돼도 Room 큐와 재시도 횟수·오류·다음 시각이 유지됩니다.
  • 하자 수정 시 서버 entity ID는 유지하고 새로운 operation UUID로 변경분을 전송합니다.
  • 서버 주소가 없는 개발 빌드에서는 데이터가 전송 대기 상태로 안전하게 유지됩니다.

6. 화면 표시

하자 상세 화면에 `로컬 저장됨·전송 대기`, `서버 전송 중`, `서버 전송 완료`, `통신 회복 후 재전송`, `서버 확인 필요`를 표시하고 실패·충돌 시 수동 `다시 전송`을 제공합니다.

8. 운영 연계 조건

  1. 운영 HTTPS API 주소를 PINSET_AI_API_BASE_URL 빌드 속성에 지정합니다.
  2. OIDC 액세스 토큰 공급자를 연결합니다. 토큰·DB 비밀번호는 APK나 Room에 평문 저장하지 않습니다.
  3. 서버에서 미디어 업로드 완료 확인과 sync batch의 applied/duplicate/conflict 처리를 검증합니다.
  4. 비행기 모드 저장 → 앱 종료·재시작 → 네트워크 회복 → 서버 조회의 실기기 E2E를 수행합니다.
