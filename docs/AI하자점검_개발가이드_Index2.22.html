PostgreSQL 품질·하자 데이터 분석 및 AI 학습 분류 재검토

v1.0 · 2026-08-03 · 읽기 전용 스키마 조사 결과 및 기존 학습 표본을 기준으로 한 실행 제안

분석 범위와 한계
현재 PowerShell 세션에는 RDS 접속 환경변수가 없어 새로운 실DB 집계는 실행하지 않았습니다. 본 보고서는 2026-07-21에 read-only로 저장된 backupdb-schema.json, 요약 파일 및 기존 3,000건 학습 표본의 구조를 근거로 합니다. 비밀번호·DSN·접속문자열은 기록하지 않았습니다. 따라서 아래의 건수는 PostgreSQL 통계 추정치이며, 학습 레이블 분포·결측률은 접속 환경 복원 후 SELECT 전용 검증으로 확정해야 합니다.

표준 분류 자산도 분리되어 있습니다: defect_area(92), defect_part(11), defect_part_detail(485), defect_work_kind(106), defect_cause(11), 그리고 세부 매핑 테이블. 이는 새 분류체계를 새로 만드는 것보다 기존 표준코드를 기준축으로 정규화하는 편이 안전하다는 뜻입니다.

2. 품질점검과 하자점검의 역할 분리

구분입력 특성학습 데이터로서의 역할처리 원칙
품질점검
(점검매니저)		근경·원경·설명 스티커, 현장 위치, 점검자 설명, 확정 분류Gold: 이미지 분류·원인·공종 평가의 기준 데이터사람 확정값만 감독 레이블로 사용. 사진 품질·중복 검사를 통과해야 함.
하자점검
(입주자/CS)		자유 의견, 편차 큰 사진, 표현·용어 불일치Bronze/Silver: 검색·문장정규화·약한 감독 학습원문은 보존하고 AI 제안은 분리. 자동 확정 레이블로 바로 쓰지 않음.

현재 표본의 라벨에는 타일·벽지·강마루·목문·창호 등 부위/자재 성격이 강합니다. 따라서 “타일”을 하자유형으로 학습하면 균열·들뜸·오염·파손을 구분하지 못합니다. 부위와 현상/원인은 반드시 별도 축으로 분리해야 합니다.

3. 권장 5계층 분류 체계

1 위치/공간
→
2 하자부위
→
3 상세부위·현상
→
4 공종
→
5 원인·조치

예: 거실 · 천장 · 도장면 균열 · 도장공사 · 건조수축/시공불량. 앱에서는 모르는 층은 “잘 모르겠음”과 자유의견을 허용하고, AI는 확률 상위 3개만 제안합니다. 최종 확정값과 원문·사진·AI 제안을 모두 별도 저장합니다.

분류 축학습/추천 입력정답 기준
위치·공간평면도 앵커, 동·호, 점검 동선, 의견 텍스트점검자 선택값
부위·상세부위이미지, 스티커 OCR, 기존 표준코드, 텍스트part / part_detail 매핑
현상·원인사진 + 자유의견 + 유사사례cause 코드와 사람 검수
공종상세부위·원인·현장 맥락work_kind 코드

4. 가장 효과적인 학습 방식: 단계형 멀티모달

단계모델/방식목적학습 대상
0. 품질 게이트규칙 + 이미지 품질 모델흐림·중복·화살표/스티커 과다·무관 사진 표기원본 보존, 정제본은 파생본으로 생성
1. 텍스트 검색한국어 임베딩 + 키워드/벡터 혼합검색450만 건에서 유사 하자·표준 표현 회수모든 원문을 사용 가능
2. 이미지 기초모델ConvNeXt-Tiny공간/부위/현상 coarse 후보 Top-3Gold·Silver 이미지 우선
3. 멀티모달 재순위이미지 점수 + 텍스트 + 위치 + 유사사례5계층 후보의 순위 결정사람 확정 레코드
4. 사람 검수·활성학습불확실성/수정률 기반 표본선정롱테일·오분류만 우선 라벨링현장 피드백

처음부터 LLM이 사진을 최종 판정하게 하지 않습니다. LLM은 점검자 원문 정리, 표준용어 제안, 유사사례 설명에 쓰고, 실제 사진 판별은 ConvNeXt-Tiny와 사람 검수 결과를 중심으로 합니다. 검출/세그멘테이션은 균열·누수 범위처럼 박스/마스크가 실제로 라벨링된 데이터가 충분할 때에만 2단계로 추가합니다.

5. 450만 건을 학습 데이터로 만드는 순서

  1. 불변 원천층: 원문, 원본 사진, 원 하자코드를 변경 없이 보관한다.
  2. Silver 정규화층: 기존 코드와 의견을 5계층에 매핑하고, 사진 해시·OCR·품질점수·근경/원경 역할을 추가한다.
  3. Gold 학습층: 점검자 확정 + 사진 품질 통과 + 레이블 충돌 없음인 사례만 먼저 채택한다.
  4. 그룹 분할: 동일 defect_id·세대·현장·유사 이미지가 train/validation/test에 섞이지 않게 현장/시점 기준으로 분리한다.
  5. 활성학습: AI Top-1/Top-3 불일치, 낮은 신뢰도, 신규 공종만 검수 큐로 보낸다.

운영 RDS에는 대용량 임베딩·재학습 테이블을 직접 만들지 말고, read-only 추출본을 별도 분석 저장소/벡터 인덱스에 적재합니다. 운영 DB는 조회·업무 트랜잭션에 집중시킵니다.

6. 평가 기준

계층 정확도각 층 Top-1 / Top-3, 특히 상세부위·공종 Macro-F1
현장 효용점검자 수정률, 추천 채택률, 입력시간 절감
안전성낮은 신뢰도 보류율, 오확정률, 현장·시점 외부검증
데이터 품질사진 연결률, 5계층 매핑률, 중복/무관 이미지 비율

핵심: 단일 정확도 하나가 아니라, “AI가 제안한 후보를 점검자가 얼마나 빨리·정확하게 확정했는가”를 최종 KPI로 관리해야 합니다.

7. 접속 복원 후 실행할 read-only 분석

  1. site_defect 기준 사진 연결률과 사진 수 분포
  2. 공간·부위·상세부위·공종·원인의 null/코드 매핑률
  3. 상위·롱테일 레이블 분포 및 최소 Gold 표본 수
  4. site/dong/ho/시점별 중복 및 train-test 누수 위험
  5. woohaja_defect_photo_tagged와 원본 파일의 결합 가능률
  6. 품질점검 확정값과 입주자 원문의 일치·불일치 패턴

모든 연결은 SET TRANSACTION READ ONLY 후 SELECT만 사용하고, 실제 COUNT(*) 전체 스캔 대신 기존 통계·표본·인덱스 범위집계를 우선 사용합니다.

결론: 다음 우선순위

  1. 기존 5계층 표준코드와 419만 하자·255만 파일의 실제 연결률을 read-only로 확정
  2. 태깅 사진 11만 건과 점검자 확정 사례로 ConvNeXt-Tiny 기준 모델 구축
  3. 450만 건 원문은 검색·약한 감독·유사사례에 우선 활용
  4. 앱의 사진/의견/최종확정 로그를 Gold 데이터로 계속 축적
