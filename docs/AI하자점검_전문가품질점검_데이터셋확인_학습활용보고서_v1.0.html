결론
별도 고품질 후보 데이터셋이 실제로 존재합니다. public.woohaja_defect_photo_tagged를 원천으로 한 DB 학습 데이터셋은 사진과 함께 공간·부위·상세부위·공종·하자원인 5개 레이블을 보유합니다. 건설사가 고용한 전문가의 확정 입력임이 실DB의 점검자·검수 상태까지 검증되면, 이 데이터는 새 AI 분류기의 최우선 Gold 데이터가 됩니다.

2. 왜 전문가 품질점검 데이터가 특별히 중요한가

일반 입주자 접수전문가 품질점검학습상 효과
자유 표현, 사진 품질 편차, 부위·원인 혼용현장 기준의 구조화된 확인, 사진·부위·공종·원인 연결 가능이미지와 표준 분류의 관계를 안정적으로 학습
“벽이 이상해요”“거실 · 벽 · 벽지/도장면 · 내장/도장공사 · 시공불량/균열”AI가 입주자 표현을 전문가 표준 문장·코드로 변환하는 근거
민원 단계의 관찰시공하자 적출·분석·확정 가능성원인·공종 추천의 감독 레이블로 활용 가능

특히 기존 사진만으로 어려운 공종과 원인은 전문가 의견·확정코드가 있어야 의미 있는 모델이 됩니다. 사진은 부위·현상 판별에 강하고, 원인은 현장 맥락과 전문가 판단을 함께 써야 합니다.

3. Gold로 확정하기 위한 필수 검증

현재 보존된 데이터셋에는 5개 레이블이 확인됐지만, 현재 PowerShell에 RDS 접속 환경변수가 없어 점검자 자격과 승인 상태의 실분포는 아직 조회하지 못했습니다. 다음 항목을 read-only로 확인해야 합니다.

  1. 입력 주체: 점검자 ID, 역할, 협력사/전문가 구분, 입력 경로
  2. 확정 상태: 초안·검토·승인·보수완료·반려 등 상태와 최종 수정자
  3. 레이블 일관성: 같은 상세부위에 여러 공종/원인이 섞이는 비율
  4. 사진 적합성: 실제 하자 사진인지, 스티커·전체·근경/원경 중 무엇인지, 중복 여부
  5. 시간성: 준공/사전점검/입주 후 AS 단계와 발생 시점
전문가 입력이라는 사실만으로 자동 Gold가 되지는 않습니다. “전문가 입력 + 최종 승인 + 사진-하자 연결 + 표준코드 완결”을 모두 만족한 행을 Gold로 지정해야 합니다. 나머지는 Silver로 보관해 검색·약한 감독 학습에 씁니다.

4. 권장 데이터 계층

5. 실제 모델 학습에 적용하는 방법

  1. Gold-Expert으로 기준 모델: ConvNeXt-Tiny를 공간·부위·상세부위의 멀티헤드 분류로 학습한다.
  2. 원인·공종은 별도 헤드: 이미지 단독 점수에 전문가 의견·공간·상세부위·유사사례를 결합해 추천한다.
  3. Silver를 사전학습에 사용: 대량의 태깅 사진으로 시각 특징을 익히되, 최종 평가는 Gold-Expert에 한정한다.
  4. Bronze의 역할 분리: LLM/임베딩으로 “입주자 말 → 표준표현”을 만들고, 확정 전에는 CNN 정답으로 쓰지 않는다.
  5. 현장 앱 피드백: AI 제안·점검자 수정·최종확정의 차이를 학습 큐로 쌓는다.

권장 출력: 위치.하자부위.상세부위.공종.원인 형식의 Top-3 후보, 신뢰도, 유사한 전문가 사례 사진/문장. 낮은 신뢰도는 “확인 필요”로만 제시하고 자동 확정하지 않습니다.

6. 다음 DB 분석 순서

  1. woohaja_defect_photo_tagged의 점검자·상태·수정자·접수 경로 후보 컬럼을 카탈로그에서 확인
  2. 전문가 확정 가능 조건별 사진 수, 하자 수, 현장 수, 5계층 완결률 집계
  3. 공간·부위·상세부위·공종·원인의 불일치와 롱테일 분포 분석
  4. 태깅 사진과 site_defect, site_defect_file를 defect_id로 결합 가능한 비율 검증
  5. Gold 후보로 소규모 5,000~20,000건을 확정해 기준 모델 재학습

운영 DB에는 UPDATE, INSERT, CREATE를 하지 않습니다. 접속 복원 후에도 SET TRANSACTION READ ONLY 및 SELECT만 사용해 분석합니다.
