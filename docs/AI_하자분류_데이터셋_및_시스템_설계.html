Apartment Defect AI · Solution Blueprint

AI 기반 하자 분류·메타데이터 생성 시스템 설계

하자 이미지를 분석하여 위치, 하자원인, 공종, 하자부위와 상세부위를 실시간으로 분류하고 서버 및 운영 DB에 안전하게 전달하기 위한 데이터셋·모델·서비스 설계안

1. 핵심 설계 원칙

권장 결론: 이미지 하나로 모든 메타데이터를 직접 결정하는 단일 평면 분류 모델보다, 이미지·접수 텍스트·현장 문맥을 결합한 계층형 멀티태스크 모델이 정확성과 운영 안정성 면에서 유리하다.

시각 정보

균열, 누수 흔적, 오염, 파손, 들뜸 등 사진에서 관찰 가능한 하자를 탐지한다.

업무 문맥

단지·동·호·실, 고객 민원, 기존 공종 후보를 함께 사용해 모호성을 줄인다.

기준정보 검증

DB의 공종·부위·상세부위 관계에 어긋나는 조합을 후보에서 제거한다.

2. 권장 데이터 원천

우선순위데이터 원천용도핵심 컬럼
1woohaja_defect_photo_tagged초기 AI 학습용 통합 데이터 photo_url, 부위, 상세부위, 공종, 하자원인
2v_defect_with_files2운영 데이터 조인 검증 full_path, part, part_detail, work_kind_name, cause_name
3site_defect_file + site_defect운영 원천 및 신규 데이터 defect_id, full_path, requirement, work_kind_id
품질 확인: 통합 테이블의 defect_id는 명시적인 FK가 없으므로 운영 데이터와의 매칭률, 중복 이미지, 경로 유효성, 라벨 충돌을 학습 전에 검사해야 한다.

6. 데이터셋 구성과 분할

학습 레코드 단위

  • 이미지 ID와 defect_id
  • 이미지 URI와 품질 상태
  • 위치·부위·상세부위 ID
  • 공종·원인과 라벨 신뢰도
  • 접수내용 및 현장 문맥
  • 중복 그룹과 출처

누수 방지 분할

  • 동일 defect_id는 한 split에만 배치
  • 동일·유사 사진 그룹을 분리하지 않음
  • 가능하면 현장 단위 분할
  • 최근 기간과 신규 현장을 별도 테스트

권장: Train 70% · Validation 15% · Test 15%와 별도의 최근 데이터 운영 검증 세트

10. 신뢰도 기반 운영 정책

신뢰도처리 정책
0.90 이상자동 저장 가능

0.50~0.70상위 3개 후보 제시
0.50 미만자동 분류 보류
계층 규칙 위반신뢰도와 무관하게 검토

실제 임계값은 공종·부위·상세부위·원인별 검증 결과로 각각 보정한다.

11. 권장 구축 순서

  1. woohaja_defect_photo_tagged 이미지 접근성과 라벨 품질 검증
  2. defect_id 기준 중복 제거 및 누수 없는 데이터 split 생성
  3. 공종·부위·상세부위를 운영 DB 기준정보 ID로 정규화
  4. 이미지 품질 모델과 기본 멀티태스크 분류 모델 구축
  5. v_defect_with_files2 및 접수 텍스트를 결합한 멀티모달 모델 확장
  6. 탐지·분할 라벨을 점진적으로 추가하고 설명 가능성 확보
  7. 추론 API, AI 전용 저장 테이블, 사용자 검수 화면 구축
  8. 사용자 수정 결과를 재학습 큐로 순환시키는 운영 체계 구축

12. MVP 권장 범위

1차 MVP: 통합 이미지 테이블로 시각 하자 유형·부위·상세부위를 학습하고, 공종과 하자원인은 이미지 예측, 접수 텍스트 및 DB 매핑 규칙을 결합해 후보로 생성한다. 검수된 결과는 AI 전용 테이블에 저장하고 다음 학습 데이터로 환류한다.
